# Proxywatch

Proxywatch предоставляет приложениям Linux постоянный адрес локального HTTP- или SOCKS5-прокси. Он проверяет, доступен ли нужный вам сервис через каждый узел. Если активный маршрут отказывает, новые соединения идут через исправный резерв на том же локальном порту.

## Возможности

- Включите HTTP, SOCKS5 (TCP) или оба протокола. По умолчанию HTTP слушает на `127.0.0.1:10809`, SOCKS5 на `127.0.0.1:10808`.
- Загружайте узлы VLESS/REALITY/Vision поверх TCP и Hysteria2 из подписки Mihomo YAML. Подойдёт ссылка из Remnawave, Marzban или 3x-ui (X-UI), если панель выдаёт совместимый список `proxies`. Профиль Hysteria2 может содержать общее поле `client-fingerprint`. Для QUIC используются настройки TLS этого профиля, включая проверку отпечатка сертификата из `fingerprint`, если он указан. Для настройки достаточно URL подписки. Если обновление подписки не удалось, Proxywatch сохраняет последний пригодный список.
- При первом замере приоритет получает узел с самым быстрым успешным HTTP-ответом. По умолчанию Proxywatch проверяет активный узел каждые 30 секунд, резервные каждые 15 минут. После трёх последовательных отказов он сразу проверяет резерв. При восстановлении приоритетного узла новые соединения возвращаются на него. При полном отказе пересылка прекращается. Уже установленные соединения могут потребовать переподключения.
- Если настроен канал уведомлений, по умолчанию сводка приходит раз в 30 минут. В Telegram она отправляется через активный прокси. При полном отказе или ошибке доставки в Telegram Proxywatch отправляет письмо напрямую по SMTP. В уведомлениях указано время UTC и местное время сервера, если оно отличается.
- Смотрите состояние узлов и историю событий в терминале или читайте состояние из скрипта. История и очередь уведомлений хранятся локально в SQLite.

## Установка и обновление

Готовые сборки доступны для Linux x86_64 и ARM64. Для установки и обновления используется одна команда:

```sh
curl -fsSLo install.sh https://github.com/nahashed/proxywatch/releases/latest/download/install.sh &&
  sudo bash install.sh
```

Если вы уже работаете от root, запускайте `bash install.sh` без `sudo`.

Установщик проверяет SHA-256 и использует уже установленный [Xray-core](https://github.com/XTLS/Xray-core) версии 26.7.28 или новее. Если Xray отсутствует или устарел, установщик автоматически ставит проверенную копию 26.7.28 в `/usr/local/lib/proxywatch/xray`. Системная копия остаётся доступна другим приложениям. На Debian или Ubuntu при онлайн-установке скрипт установит `unzip` через APT, если отсутствуют и `unzip`, и Python 3. Для установки без диалога используйте `--non-interactive`. Параметры для автономной установки и выбора версии перечислены в `bash install.sh --help`.

Обновление сохраняет настройки и базу данных. При повторной установке той же сборки файлы и работающая служба сохраняются. При замене файлов установщик перезапускает активную штатную службу текущего пользователя, если она доступна, и сообщает, когда нужен ручной перезапуск. Запускайте Proxywatch командой `proxywatch`. Короткое имя `pwch` устанавливается, если оно свободно. Чтобы команды находились и в консоли Proxmox `pct enter`, установщик добавляет ссылки в `/usr/bin`, если имена свободны. Полный путь к программе `/usr/local/bin/proxywatch`.

## Первый запуск

1. При интерактивном запуске установщик открывает мастер, если у текущего пользователя ещё нет настроек. Это работает и при повторе после прерванной установки. Открыть её снова можно командой `proxywatch`. Выберите язык, задайте имя установки, укажите ссылку на подписку и URL сервиса, доступность которого нужно проверять.
2. Выберите локальные протоколы и порты. Если нужный порт уже слушает другой Xray, сначала проверьте Proxywatch на свободном порту. Чтобы сохранить привычный адрес, воспользуйтесь переносом портов. При необходимости настройте Telegram, SMTP или идентификатор устройства для подписки.
3. Сохраните настройки. При запуске от root в консоли контейнера без пользовательского systemd Proxywatch включает системную службу `proxywatch.service` для конфигурации в `/root/.config/proxywatch`. Служба продолжает работать после закрытия терминала. Её состояние можно посмотреть командой `systemctl status proxywatch.service`. В сеансе обычного пользователя мастер использует его пользовательскую службу. Если systemd недоступен, мастер предложит запуск в терминале. Укажите выбранный локальный адрес в своём приложении.

Командой `proxywatch` можно изменить настройки, посмотреть причины пропуска узлов при чтении подписки и открыть историю событий. Каталог данных по умолчанию находится в `~/.config/proxywatch` (или `$XDG_CONFIG_HOME/proxywatch`). Для отдельного экземпляра укажите `--directory PATH`.

В разделе «Проверки и интервалы» можно выбрать дополнительные ресурсы или добавить свои URL. Enter оставляет предложенный интервал. Например, задайте для Gemini `86400` секунд, чтобы проверять его раз в сутки, и оставьте для основной проверки Telegram `30` секунд. Результаты дополнительных запросов видны в статусе. Переключением узлов управляет основная проверка.

### Уведомления

В разделе **«Настройки → Уведомления»** выберите периодическую сводку или отправку только при изменениях и задайте интервал. Первый отчёт может прийти сразу. Последующие изменения за интервал объединяются в одно сообщение. Подробные события остаются в локальной истории. Бот отправляет сообщения в указанный чат. Вставьте полный токен из BotFather в формате `ID_бота:секрет` и введите ID чата. Proxywatch хранит эти данные в `settings.json` с доступом для владельца службы.

### Переход с работающего Xray на тех же портах

Введите новую подписку в мастере и выберите локальные порты, которые уже используют ваши приложения. Если порты свободны, обе службы могут работать одновременно. При первой настройке от root установленный Proxywatch также может предложить передачу портов выделенной системной службы `xray.service`. Мастер определяет HTTP и SOCKS5 по конфигурации запущенного Xray, сверяет владельца слушающих сокетов и сохраняет за каждым протоколом его прежний порт. Если Xray слушает и HTTP, и SOCKS5, выберите оба входа перед переносом службы.

Если при настройке порт занят, мастер откроет экран конфликта портов. С сохранёнными настройками этот экран доступен из главного меню. На нём видны локальный адрес, владелец порта, если его удалось определить, и причина, по которой перенос пока невозможен. Подписку можно проверить на временном порту, пока старый прокси обслуживает клиентов. Когда будете готовы к переносу, приостановите клиентов и проверьте порты ещё раз. Также можно выбрать другой порт и оставить обе службы работать одновременно.

При выборе перехода мастер проверяет новую подписку через временный прокси. Старый Xray в это время обслуживает клиентов. После успешной проверки мастер запрашивает разрешение остановить службу и ещё раз проверяет подключения. При переключении будет короткий перерыв. Если проверка нового маршрута на выбранных портах не пройдёт, Proxywatch попытается вернуть Xray. Если владелец портов неизвестен, служба обслуживает другие входы либо настроены авторизация или UDP, можно выбрать свободные порты или перенести нужный вход вручную.

Для пробы выберите временный перенос. Обе службы сохранят прежние настройки автозапуска. При запуске в терминале Ctrl+C возвращает порты Xray.

Для постоянного переноса откройте `proxywatch` (или `pwch`) от root и откройте **«Устранить конфликт портов»** и выберите перенос. Если доступна установленная системная служба, выберите **«Постоянно, запускать Proxywatch при загрузке»**. Если Xray может запустить другая служба systemd, мастер объяснит, почему постоянный перенос недоступен. Мастер проверит трафик на прежних портах, затем включит автозапуск `proxywatch.service` и отключит автозапуск `xray.service`. Этим же пунктом можно воспользоваться с сохранённой конфигурацией, если после перезагрузки порты снова занял Xray. При повторяющихся ошибках запуска systemd ограничивает число попыток. Чтобы вернуть порты и автозапуск Xray после постоянного переноса, остановите системную службу Proxywatch и отключите её автозапуск, затем включите и запустите `xray.service`.

## CLI для скриптов и агентов

Выполняйте команды от имени владельца конфигурации. Ограничьте доступ к файлам с учётными данными.

```sh
proxywatch configure --stdin < settings.json
proxywatch configure --stdin --merge < changes.json
proxywatch status --json
```

Минимальный файл настроек содержит `{"subscription_url":"https://example.invalid/subscription"}`. Первая команда записывает полную конфигурацию и подставляет значения по умолчанию для пропущенных полей. Для изменения отдельных полей существующей конфигурации используйте `--merge`. Вложенные объекты объединяются, массивы заменяются целиком. Например, `{"socks_port":null}` отключает SOCKS5 и сохраняет настройки HTTP. Перед сохранением Proxywatch проверяет входные данные. После изменения настроек через CLI перезапустите работающий процесс.

Если провайдеру нужен идентификатор устройства, задайте `subscription_hwid` как `true` для автоматического ID на основе идентификатора машины Linux и адреса источника подписки или укажите свою строку, например `"my-x-hwid-01"`. Автоматический ID состоит из 64 шестнадцатеричных символов (HMAC-SHA256). Свой ID может содержать от 10 до 64 латинских букв, цифр, дефисов или знаков равенства. Используйте свой ID там, где у вас есть право его назначать. По умолчанию передача выключена (`false`). При включении Proxywatch передаёт заголовок `x-hwid` в HTTPS-запросах подписки к настроенному источнику.

Чтобы отправлять сводку каждые полчаса, передайте команде `proxywatch configure --stdin --merge` объект `{"notification_mode":"summary","notification_interval_seconds":1800}`. Для отправки только при изменениях выберите `"changes"`.

В массиве `diagnostic_urls` строка URL наследует интервал основной проверки. Объект с `interval_seconds` задаёт отдельный интервал в секундах. Пример для `--merge`.

```json
{"diagnostic_urls":["https://example.org/",{"url":"https://gemini.google.com/","interval_seconds":86400}]}
```

`status --json` возвращает последний сохранённый снимок, включая количество узлов, время обновления в формате Unix и число уведомлений в очереди. Ключи и значения JSON, а также коды выхода одинаковы при любом языке интерфейса. Код `0` означает успех, `1` указывает на ошибку настройки или выполнения, `2` на ошибку в синтаксисе команды.
