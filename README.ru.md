# Proxywatch

Proxywatch предоставляет приложениям Linux постоянный адрес локального HTTP- или SOCKS5-прокси. Он проверяет, доступен ли нужный вам сервис через каждый узел. Если активный маршрут отказывает, новые соединения идут через исправный резерв на том же локальном порту.

## Возможности

- Включите HTTP, SOCKS5 (TCP) или оба протокола. По умолчанию HTTP слушает на `127.0.0.1:10809`, SOCKS5 на `127.0.0.1:10808`.
- Загружайте узлы VLESS/REALITY/Vision поверх TCP и Hysteria2 из подписки Mihomo YAML. Подойдёт ссылка из Remnawave, Marzban или 3x-ui (X-UI), если панель выдаёт совместимый список `proxies`. Для настройки достаточно URL подписки. Если обновление подписки не удалось, Proxywatch сохраняет последний пригодный список.
- При первом замере приоритет получает узел с самым быстрым успешным HTTP-ответом. По умолчанию Proxywatch проверяет активный узел каждые 30 секунд, резервные каждые 15 минут. После трёх последовательных отказов он сразу проверяет резерв. При восстановлении приоритетного узла новые соединения возвращаются на него. При полном отказе пересылка прекращается. Уже установленные соединения могут потребовать переподключения.
- Получайте уведомления в Telegram через активный прокси. При полном отказе или ошибке доставки в Telegram Proxywatch отправляет письмо напрямую по SMTP. Время событий указано в UTC.
- Смотрите состояние узлов и историю событий в терминале или читайте состояние из скрипта. История и очередь уведомлений хранятся локально в SQLite.

## Установка и обновление

Готовые сборки доступны для Linux x86_64 и ARM64. Для установки и обновления используется одна команда:

```sh
curl -fsSLo install.sh https://github.com/nahashed/proxywatch/releases/latest/download/install.sh &&
  sudo bash install.sh
```

Установщик проверяет архив по SHA-256. Для работы нужен [Xray-core](https://github.com/XTLS/Xray-core) версии 26.7.28 или новее. Если подходящей версии нет, интерактивный установщик предложит поставить проверенную копию Xray 26.7.28 в `/usr/local/lib/proxywatch/xray`. Системная установка Xray при этом сохраняется. Для распаковки нужен unzip или Python 3. Для автоматической установки используйте `--non-interactive --with-xray`. Параметры для установки из локальных файлов и выбора версии перечислены в `bash install.sh --help`.

Обновление сохраняет настройки и базу данных. При повторной установке той же сборки файлы и работающая служба сохраняются. При замене файлов установщик перезапускает активную штатную службу текущего пользователя, если она доступна, и сообщает, когда нужен ручной перезапуск. Основная команда называется `proxywatch`. Если имя `pwch` свободно, установщик добавляет это сокращение.

## Первый запуск

1. При первой интерактивной установке настройка открывается от имени пользователя, запустившего установщик. Открыть её снова можно командой `proxywatch`. Выберите язык, задайте имя установки, укажите ссылку на подписку и URL сервиса, доступность которого нужно проверять.
2. Выберите локальные протоколы и порты. При необходимости настройте Telegram, SMTP или идентификатор устройства для подписки.
3. Сохраните настройки. Если доступен пользовательский экземпляр systemd, Proxywatch включит и запустит свою установленную службу. В остальных случаях интерфейс покажет команду запуска в терминале. Укажите выбранный локальный адрес прокси в приложении.

Командой `proxywatch` можно изменить настройки, посмотреть причины пропуска узлов при чтении подписки и открыть историю событий. Каталог данных по умолчанию находится в `~/.config/proxywatch` (или `$XDG_CONFIG_HOME/proxywatch`). Для отдельного экземпляра укажите `--directory PATH`.

## CLI для скриптов и агентов

Выполняйте команды от имени владельца конфигурации. Ограничьте доступ к файлам с учётными данными.

```sh
proxywatch configure --stdin < settings.json
proxywatch configure --stdin --merge < changes.json
proxywatch status --json
```

Минимальный файл настроек содержит `{"subscription_url":"https://example.invalid/subscription"}`. Первая команда записывает полную конфигурацию и подставляет значения по умолчанию для пропущенных полей. Для изменения отдельных полей существующей конфигурации используйте `--merge`. Вложенные объекты объединяются, массивы заменяются целиком. Например, `{"socks_port":null}` отключает SOCKS5 и сохраняет настройки HTTP. Перед сохранением Proxywatch проверяет входные данные. После изменения настроек через CLI перезапустите работающий процесс.

Если провайдеру нужен идентификатор устройства, задайте `subscription_hwid` как `true` для автоматического ID на основе идентификатора машины Linux и адреса источника подписки или укажите свою строку, например `"my-x-hwid-01"`. Автоматический ID состоит из 64 шестнадцатеричных символов (HMAC-SHA256). Свой ID может содержать от 10 до 64 латинских букв, цифр, дефисов или знаков равенства. Используйте свой ID там, где у вас есть право его назначать. По умолчанию передача выключена (`false`). При включении Proxywatch передаёт заголовок `x-hwid` в HTTPS-запросах подписки к настроенному источнику.

`status --json` возвращает последний сохранённый снимок, включая количество узлов, время обновления в формате Unix и число уведомлений в очереди. Ключи и значения JSON, а также коды выхода одинаковы при любом языке интерфейса. Код `0` означает успех, `1` указывает на ошибку настройки или выполнения, `2` на ошибку в синтаксисе команды.
