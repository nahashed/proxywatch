# Proxywatch

Укажите приложению один локальный адрес HTTP- или SOCKS5-прокси. Если через текущий узел перестанет открываться нужный сервис, Proxywatch направит новые соединения через рабочий резерв на том же порту. Если недоступны все узлы, передача остановится. Напрямую трафик не пойдёт.

Proxywatch работает в Linux. Для соединений он использует [Xray](https://github.com/XTLS/Xray-core), а узлы получает из подписки в формате Mihomo YAML. API панели и токен администратора не нужны.

## Возможности

- Можно включить только HTTP, только SOCKS5 TCP или оба протокола на разных локальных портах.
- Proxywatch проверяет доступность выбранного сервиса через каждый узел. При подтверждённом отказе новые соединения идут через рабочий резерв на том же локальном порту. После восстановления трафик возвращается на приоритетный узел.
- Подписка Mihomo YAML со списком `proxies` поддерживает VLESS/REALITY/Vision поверх TCP и Hysteria2. В меню видны причины пропуска записей. При ошибке обновления сохраняется последняя рабочая подписка.
- Уведомления приходят в Telegram через активный прокси. При полном отказе или ошибке доставки можно получить письмо через прямое SMTP-соединение. Меню и уведомления доступны на русском и английском.
- Настройки можно передать через стандартный ввод, а статус получить в JSON. История узлов и очередь уведомлений хранятся локально в SQLite.

## Установка

Готовые сборки для Linux рассчитаны на x86_64 и aarch64 с glibc и проверены на Debian 12. Установите Xray отдельно (проверено с 26.7.28). Если его нет в `PATH`, укажите полный путь в меню настройки. Для публичного релиза скачайте и запустите установщик:

```sh
curl -fsSLo install.sh https://github.com/nahashed/proxywatch/releases/latest/download/install.sh &&
  sudo bash install.sh
```

Установщик выбирает последний стабильный релиз для архитектуры Linux, сверяет SHA-256 архива и устанавливает `proxywatch`. Если команда `pwch` свободна, она тоже будет открывать Proxywatch. Установщик не меняет настройки Xray и не запускает службу.

Для обновления снова выполните `sudo bash install.sh`. Если установленные файлы совпадают с проверенным релизом, установщик успешно завершится без их замены. При обновлении настройки и база SQLite сохраняются. Чтобы запущенный экземпляр Proxywatch перешёл на новую версию, перезапустите его. Для пользовательской службы systemd выполните `systemctl --user daemon-reload && systemctl --user restart proxywatch.service` от имени владельца службы.

Для приватного релиза или машины без интернета возьмите установщик из локального репозитория, а архив и файл `SHA256SUMS` из доверенного релиза. Поместите архив и файл контрольных сумм в `./release` и выполните `sudo bash install.sh --from ./release --version v0.1.0`. До появления релиза можно собрать проект командой `cargo build --release --locked` и запустить `./target/release/proxywatch`.

## Первый запуск

1. Запустите `proxywatch` от имени пользователя, под которым будет работать служба. При первой настройке выберите English или Русский. Задайте имя установки, ссылку на подписку и URL сервиса, который должен открываться через прокси.
2. Выберите HTTP, SOCKS5 (TCP) или оба на разных портах. По умолчанию HTTP слушает на `127.0.0.1:10809`, SOCKS5 на `127.0.0.1:10808`. Если на машине уже работает прокси, выберите свободные порты.
3. Сохраните настройки. Для запуска в текущем терминале выполните `proxywatch run`, для работы в фоне включите пользовательскую службу systemd:

```sh
systemctl --user daemon-reload
systemctl --user enable --now proxywatch.service
```

Укажите локальный порт в настройках приложения. Снова откройте `proxywatch`, чтобы посмотреть текущий маршрут, состояние узлов и историю событий. После изменения настроек перезапустите службу. Если она должна работать после выхода пользователя из системы, включите для его учётной записи режим lingering.

## Автоматизация

Выполняйте команды от имени владельца службы. Передайте объект настроек через стандартный ввод. Файл может содержать данные доступа, поэтому ограничьте права на чтение. Минимальный пример с условным адресом подписки:

```json
{"subscription_url":"https://example.invalid/subscription"}
```

```sh
proxywatch configure --stdin < settings.json
proxywatch status --json
```

Для одного входа укажите `null` в поле второго порта. Например, при `"socks_port": null` работает только HTTP. Пропущенное поле получает порт по умолчанию.

Команда настройки заменяет весь объект. Пропущенные поля получают значения по умолчанию. Неизвестные поля вызывают ошибку. Проверка выполняется до записи. При успехе команда завершается без вывода. Чтобы применить настройки к запущенной службе, перезапустите её.

Команда статуса читает последний сохранённый снимок. JSON содержит версию схемы, признак наличия настроек, состояние службы, время обновления в формате Unix, признак использования приоритетного узла, число узлов и количество уведомлений в очереди. Команда доступна и до первого запуска. Код выхода 0 означает успех, 1 указывает на ошибку операции или настроек, 2 на ошибку синтаксиса команды.

До первой настройки статус выглядит одинаково для обоих языков:

```json
{"schema_version":1,"configured":false,"status":"unknown","updated_at":0,"active_is_preferred":null,"nodes_total":0,"nodes_available":0,"pending_notifications":0}
```

Поле `"language": "ru"` или `"language": "en"` задаёт язык меню, сообщений CLI и уведомлений. Язык также можно изменить в настройках. Для существующих конфигураций по умолчанию используется русский. JSON статуса и коды выхода одинаковы для обоих языков.

## Что происходит при отказе?

Допустим, A выбран основным узлом, а B находится в резерве. По умолчанию Proxywatch проверяет A каждые 30 секунд. После трёх ошибок подряд он проверяет резерв. Если B проходит ту же проверку, **новые соединения идут через B**. Адрес прокси в приложении не меняется, но уже открытые соединения может потребоваться установить заново. Как только A снова пройдёт проверку, **новые соединения вернутся на A**, даже если B исправен.

- **Выбор узла.** При первом обходе Proxywatch выбирает узел с самым быстрым успешным HTTP-ответом (2xx или 3xx). Это время доступа к сервису через прокси, а не ICMP-пинг. Приоритет сохраняется при перезапуске. По умолчанию резерв проверяется каждые 15 минут и при отказе текущего выхода. Дополнительные диагностические URL не вызывают переключений.
- **Локальные данные.** История и очередь уведомлений каждой установки хранятся в SQLite в `~/.config/proxywatch` (или `$XDG_CONFIG_HOME/proxywatch`). Там же лежат данные доступа к подписке и каналам уведомлений. Не открывайте каталог другим пользователям. Для отдельного экземпляра укажите `--directory PATH`.
